# Git操作 for Finder

Git対象フォルダ内の右クリック（Control＋クリック）コンテキストメニューから日常的な Git 操作を実行する macOS アプリです。「Git操作」はプルダウン形式のサブメニューとして表示されます。

## 実装済みメニュー

- Git操作
  - 同期・リモート操作: 同期、Pull、Push、Fetch、Clone
  - コミット関連: Commit、Show Log、変更の確認、Diff、前版とのDiff
  - 作業ツリー操作: Add、Delete / Remove、Rename / Move、Revert、Ignore
  - ブランチ・履歴操作: ブランチ作成、切り替え、Merge、Rebase、Reset、Stash保存／復元、Tag作成、Blame、ブランチ画像
  - パッチ・サブモジュール: Patch作成／適用、Submodule Update
  - Shift＋右クリックの高度な操作: Bisect、Cleanup
  - Git対象フォルダを追加
  - Finder拡張機能を有効にする
  - 設定
  - バージョン情報

Git操作はFinderのコンテキストメニューに統一しており、アプリ単体の操作画面や選択画面は自動表示しません。

「作業ツリー操作 → 追加…」は、Finderでファイルを選択している場合はその項目を直接ステージします。ファイルを選択せずフォルダ内の空白部分から実行した場合は選択パネルを開き、複数のファイル／フォルダをまとめてステージします。追加後はFinderのバッジを「追加済み」へ更新します。

フォルダには配下のGit状態を集約したフォルダ形バッジを表示します。競合、変更、削除、追加、未登録、無視対象の優先順で代表状態を表示するため、フォルダを開かなくても中に対応が必要な項目があることを確認できます。

未管理フォルダでは「リポジトリのクローン」と「ここにリポジトリを作成」を表示します。Git管理下では上記の機能別サブメニューを表示し、ファイルにだけ使えるBlameなどは選択状態に応じて有効化します。

コミットは `git add --all` の後に実行します。プルは意図しないマージコミットを避けるため `git pull --ff-only`、Resetは作業ファイルを残す `--mixed` で実行します。Delete、Revert、Rebase、Reset、Stash復元、Patch適用、Cleanupなどは実行前に確認画面を表示します。

「Gitに登録しないファイルを追加…」は、Finderで選択したファイル／フォルダ（複数選択可）をリポジトリ直下の `.gitignore` に重複なく登録します。「ブランチを画像で表示…」は全ブランチの直近200コミットをグラフ画像としてスクロール可能な画面に表示します。

アプリ起動中はmacOSのメニューバーにGitアイコンが表示されます。アイコンのメニューから「Git対象フォルダを追加…」、Finder拡張機能の管理、設定、アプリ終了を実行できます。

アプリは一つのプロセスだけ起動します。起動済みの状態でもう一度開いた場合、新しいプロセスは作らず、既存のアプリを前面へ表示します。

## Finderアイコンオーバーレイ

Git対象フォルダとその配下には、Gitの状態に応じたアイコンオーバーレイを表示します。
アイコン、リスト、カラム表示では状態バッジを表示します。ギャラリー表示では右側の情報欄にある「タグ」へ `Git状態: 変更あり` の形式で状態を表示します。既存のFinderタグは保持し、本アプリが追加した `Git状態:` タグだけを状態変化に合わせて更新します。

- 緑のチェック: 正常（Normal）
- 赤い感嘆符: 変更あり（Modified）
- 黄色の感嘆符: 競合（Conflict）
- 青いプラス: 追加済み（Added）
- 赤いマイナス: 削除予定（Deleted。親フォルダへ集約表示）
- 紫の斜線: Git管理対象外（Ignored）
- オレンジの疑問符: 未登録（Unversioned）

フォルダは配下の状態を集約して表示します。複数の状態がある場合は、競合、変更、削除、追加、未登録、管理対象外、正常の順に優先します。

## リポジトリ設定

アプリの「リポジトリ設定…」または Finder の「Git操作 → 設定…」から、次を確認・変更できます。

- Gitが利用可能か確認し、未導入の場合はmacOS Command Line Toolsのインストールを開始
- GitHubリポジトリにする作業フォルダの選択（未初期化なら `main` で `git init`）
- 作業フォルダ直下の `.env` から作業者名、メールアドレス、GitHubユーザー名、トークンを読込
- 公開／非公開を選択してGitHub上にリポジトリを作成
- `https://github.com/ユーザー名/リポジトリ名.git` 形式の `origin` を設定
- GitHub APIによる作成後の接続テスト
- リポジトリのルートパス、現在のブランチ、Gitバージョン
- リポジトリ固有の `user.name` と `user.email`
- `origin` リモートURL（未設定の場合は新規追加）
- GitHub接続状況（`origin` への読み取り接続を確認。空のリポジトリにも対応）

設定は対象リポジトリのローカル設定にだけ保存され、グローバルGit設定は変更しません。設定画面を開くとGitHub接続を自動確認します。リモートが空の場合は、未コミットファイルをステージせず、既存のローカルコミットまたは空の初期コミットを `main` として送信してから再確認します。

「設定を保存」では作業者名、メールアドレスに加え、GitHubユーザー名、リポジトリ名、公開範囲もリポジトリ固有の `.git/config` へ保存します。GitHubトークンは保存対象に含めません。

接続確認時にGitHub上のリポジトリがまだ存在しない場合、404のAPI障害とは表示せず、「未作成」と表示してリポジトリ作成操作を案内します。

作業フォルダの選択パネルは、設定画面の「作業フォルダを選択…」を押したときだけ表示されます。
選択したフォルダの親が別のGitリポジトリでも、親へ切り替えず、選択したフォルダそのものを新しいリポジトリルートとして使用します。

### `.env` の準備

作業フォルダ直下に `.env.example` を参考に `.env` を作成します。

```dotenv
GIT_USER_NAME="Your Name"
GIT_USER_EMAIL="you@example.com"
GITHUB_USERNAME="your-github-name"
GITHUB_TOKEN="github_pat_xxxxxxxxxxxxxxxxxxxx"
```

`GITHUB_TOKEN`には、リポジトリ作成権限を持つFine-grained personal access tokenを指定してください。GitHubの現在の仕様では「Repository creation: write」または「Administration: write」が必要です。

`.env`は読込時に `.gitignore` へ自動追加されます。トークンは画面へ表示せず、`.git/config`やアプリ設定にも保存しません。GitHub APIへの認証時だけメモリ上で使用します。

### GitHubリポジトリの作成手順

1. メニューバーのGitアイコンから「設定…」を開きます。
2. 「Gitを確認／インストール」でGitを確認します。未導入なら表示されるCommand Line Toolsの案内を完了します。
3. 「作業フォルダを選択…」で対象を選びます。
4. 「.envを読み込む」を押し、作業者情報とGitHub情報を反映します。
5. リポジトリ名と公開範囲を確認し、「GitHubリポジトリを作成」を押します。
6. 「接続成功」が表示され、`origin` URLが設定されたことを確認します。

## 必要環境

- macOS 13 以降
- Git（macOS の `/usr/bin/git` を使用）
- ビルドには完全版の Xcode が必要

## ビルドと起動

1. `GitOperation.xcodeproj` を Xcode で開きます。
2. Scheme `GitOperation`、実行先 `My Mac` を選択してRunを実行します。
3. システム設定 → 一般 → ログイン項目と機能拡張 → Finder で「Git操作」を有効にします。
4. Finderで右クリック／Control＋クリックし、「Git操作 → Git対象フォルダを追加…」から対象を登録します。
5. Finderを開き直し、Git対象フォルダまたはその配下でコンテキストメニューを使用します。

Git対象フォルダを追加する場合は、Finderの「Git操作 → Git対象フォルダを追加…」を使用します。選択時にGitリポジトリと `main` の初期値を登録し、`origin` が設定済みで空ならリモート側にも初期 `main` を登録します。`origin` がない場合は設定画面でURLを登録してください。

Finder拡張の管理画面は「Git操作 → Finder拡張機能を有効にする…」から開けます。

コマンドラインからは次でもビルドできます。

```sh
./Scripts/build.sh
```

`xcode-select` がCommand Line Toolsを指している場合でも、`/Applications/Xcode.app` が存在すればビルドスクリプトが自動的に完全版Xcodeを使用します。プロジェクトが外部ボリューム上にある場合は、XcodeのビルドDBロックを避けるため内部の一時領域でビルドし、完成したアプリを `$TMPDIR/GitOperationRelease/GitOperation.app` に配置します。

署名なしビルドを `/Applications` に配置する場合は、ローカル環境のセキュリティ設定に合わせて署名してください。通常は Xcode から Run するのが最も簡単です。

ビルドスクリプトはFinder Sync ExtensionをSandbox／共有設定エンタイトルメント付きでアドホック署名し、その後に親アプリを署名します。拡張の署名を個別に行わず親アプリだけを再署名すると、Finderの状態バッジが表示されなくなるため、生成済みアプリへ追加の `codesign --deep` は実行しないでください。

## 認証

GitHubリポジトリの作成とAPI接続テストでは `.env` の `GITHUB_TOKEN` を一時的に使います。作成後のプッシュ、プル、プライベートリポジトリのクローンでは、Git に設定済みのSSH鍵またはmacOSキーチェーンの認証情報を使います。このアプリはパスワードやトークンを保存しません。

- GITHUB_TOKENの取得

``` Bash
gh auth token
```

## テスト

Git コマンド組み立てとリポジトリ探索は Swift Package として分離されています。

```sh
swift run GitCoreSelfTest
```

自己テストは、実際の Git 起動、リポジトリルート探索、コミット、同期、ファイル操作、ブランチ・履歴操作、パッチ、サブモジュール、Bisect、Cleanup、リポジトリ設定、`.env`解析、GitHub URL検証、GitHub接続、`.gitignore`、ブランチグラフ、Git状態解析を検証します。

## 現在の制限

- 「Git操作」は、Git対象フォルダ内の右クリック／Control＋クリックでプルダウン形式のサブメニューとして表示されます。
- Finder Sync Extension を初回にシステム設定で有効にする必要があります。
- セキュリティ保護のため、メニューはアプリで明示的に選択したGit対象フォルダとその配下だけに表示されます。
- コンフリクトの自動解消、コミット単位の対話型選択、外部差分ビューアとの連携は未実装です。現在はGitのテキスト出力を結果画面に表示します。
